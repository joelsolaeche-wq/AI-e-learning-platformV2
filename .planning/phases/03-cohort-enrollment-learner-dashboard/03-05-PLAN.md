<objective>
Close Gap 2 (ROADMAP SC-5: enrollment-scoped RLS on lessons).

The current lessons SELECT policy in migration 00002 allows any authenticated user to read lesson rows for any published course regardless of enrollment. ROADMAP SC-5 requires that unenrolled users receive zero rows from the lessons table.

Fix: Create a new migration (20260428000004) that drops the permissive lessons policy and replaces it with an enrollment-scoped policy. The new policy permits SELECT only when the querying user has an active enrollment in a cohort whose course contains the lesson's module.

After writing the migration, run `supabase db push` to apply it to the connected database.

Purpose: ROADMAP SC-5 is an explicit pre-condition for Phase 4 (the lesson page will query lessons; if any authenticated user can read them regardless of enrollment, the lesson page can be accessed by unenrolled users even without a server-side auth guard).

Output:
- supabase/migrations/20260428000004_lesson_enrollment_rls.sql: DROP old policy + CREATE enrollment-scoped policy.

```sql
-- ============================================================
-- Migration: 20260428000004_lesson_enrollment_rls
-- Phase 3: Cohort Enrollment + Learner Dashboard (gap closure)
-- Replaces the permissive lessons SELECT policy (which allowed
-- any authenticated user to read lessons for published courses)
-- with an enrollment-scoped policy that restricts lesson reads
-- to users enrolled in a cohort for that lesson's course.
-- This satisfies ROADMAP SC-5.
-- ============================================================

-- ------------------------------------------------------------
-- Step 1: Drop the old permissive policy
-- The policy name must match exactly as created in migration 00002.
-- ------------------------------------------------------------
drop policy if exists "Authenticated users can view lessons of published courses"
  on public.lessons;

-- ------------------------------------------------------------
-- Step 2: Create enrollment-scoped SELECT policy
-- A user can read a lesson row only when they have an active
-- enrollment in at least one cohort whose course contains the
-- module that owns this lesson.
--
-- Path: lessons.module_id → modules.course_id
--       → cohorts.course_id → enrollments.cohort_id
--       → enrollments.user_id = auth.uid()
-- ------------------------------------------------------------
create policy "enrolled users can view lessons"
  on public.lessons
  for select
  using (
    exists (
      select 1
      from public.enrollments e
      join public.cohorts c on c.id = e.cohort_id
      join public.modules m on m.course_id = c.course_id
      where e.user_id = auth.uid()
        and m.id = lessons.module_id
    )
  );
```

Notes for the executor:
- Use `DROP POLICY IF EXISTS` so the migration does not fail if somehow the policy was already dropped manually.
- The new policy name is `"enrolled users can view lessons"` — all lowercase, no "Authenticated" prefix. This matches the naming convention shift seen in migration 00003.
- The JOIN path is: enrollments (user_id = auth.uid()) → cohorts (course_id) → modules (id = lessons.module_id). This is one hop shorter than going through courses because modules already carry course_id.
- Do NOT add `and e.status = 'active'` to the enrollment filter in Phase 3 — keeping the policy simple ensures it does not accidentally block users whose enrollment row has status 'dropped' or 'completed' during Phase 4 testing. The status filter is a Phase 4+ hardening concern.
- Do NOT modify any other table's RLS in this file.
