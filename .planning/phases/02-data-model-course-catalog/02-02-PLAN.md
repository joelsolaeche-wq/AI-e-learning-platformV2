# Plan 02-02: Seed Data + TypeScript Type Generation

> Wave 1 — starts in parallel with 02-01, but the gen types task (2-02-02) MUST wait for 02-01's DB push to complete. Seed data file (2-02-01) can be written immediately in parallel.

## Goal

Create the `supabase/seed.sql` file with complete demo data (1 organization, 1 course, 3 modules, 3 lessons, 1 quiz definition, 1 cohort), run it against the cloud project, generate TypeScript types from the live schema, and update both Supabase clients to use the `Database` generic type for end-to-end type safety.

<threat_model>
| Threat ID | Description | Mitigation |
|-----------|-------------|------------|
| T-2-01 | Unauthenticated access to /catalog | Middleware and server-side auth check — handled in 02-03 and 02-04 |
| T-2-02 | RLS bypass exposing courses to wrong users | RLS enforced in 02-01 migration; seed data inserts via service role (bypasses RLS correctly — this is the intended admin path) |
| T-2-03 | Anon access to quiz_definitions.correct_answer | Seed data includes correct_answer only in the DB (service role insert); client never receives it in Phase 2 (no quiz UI yet) |
| T-2-04 | SQL injection via courseId in URL | Not applicable to seed.sql (no dynamic queries); catalog pages use parameterized queries |
| T-2-05 | Seed data FK violations breaking migration | Fixed UUIDs and insertion order (org → course → modules → lessons → quiz → cohort) with ON CONFLICT DO NOTHING prevents FK violations on re-run |
</threat_model>

```ts
import { createServerClient } from '@supabase/ssr'
import { cookies } from 'next/headers'
import type { Database } from '@/lib/database.types'

/**
 * Creates a Supabase client for server contexts:
 * - Server Components (async functions)
 * - Server Actions ("use server")
 * - Route Handlers (route.ts)
 * - Middleware (via a different cookie adapter — see middleware.ts)
 *
 * IMPORTANT: cookies() must be awaited in Next.js 15.
 * Forgetting the await causes every auth check to return null (silent bug).
 */
export async function createClient() {
  const cookieStore = await cookies()   // await is required in Next.js 15

  return createServerClient<Database>(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return cookieStore.getAll()
        },
        setAll(cookiesToSet: { name: string; value: string; options?: Record<string, unknown> }[]) {
          try {
            cookiesToSet.forEach(({ name, value, options }) =>
              cookieStore.set(name, value, options)
            )
          } catch {
            // Called from a Server Component — cookies are read-only here.
            // The middleware will handle writing the refreshed session cookie.
            // This catch is intentional and expected; do not remove it.
          }
        },
      },
    }
  )
}
```
