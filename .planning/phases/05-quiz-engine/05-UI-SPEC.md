Dark mode only (forced). All values are OKLCH CSS custom properties from `app/globals.css`. Quiz engine adds two semantic overlay patterns using existing tokens — no new CSS variables introduced.

| Role | CSS Token | OKLCH Value | Usage |
|------|-----------|-------------|-------|
| Dominant (60%) | `--background` | `oklch(0.145 0 0)` | Page background |
| Secondary (30%) | `--card` | `oklch(0.205 0 0)` | Quiz section card, answer option background |
| Muted surfaces | `--muted` | `oklch(0.269 0 0)` | Unselected answer option hover, locked state background |
| Primary text | `--foreground` | `oklch(0.985 0 0)` | Question text, answer option labels |
| Muted text | `--muted-foreground` | `oklch(0.708 0 0)` | Question counter, disabled hint text |
| Border | `--border` | `oklch(1 0 0 / 10%)` | Answer option borders, card borders |
| Primary (accent) | `--primary` | `oklch(0.922 0 0)` | Selected answer highlight (ring/border), "Submit Quiz" CTA, correct answer indicator |
| Destructive | `--destructive` | `oklch(0.704 0.191 22.216)` | Incorrect answer indicator |

### Quiz-Specific Semantic Color Patterns

These are Tailwind utility combinations applied to existing tokens — no new CSS variables:

| State | Visual Treatment | Tailwind Classes |
|-------|-----------------|-----------------|
| Answer option: unselected | Muted border, card background | `border border-border bg-card` |
| Answer option: selected (pre-submit) | Primary ring, slightly elevated border | `border border-primary ring-1 ring-primary/30 bg-card` |
| Answer option: correct (post-submit) | Green semantic — use `text-green-400 border-green-500/50 bg-green-950/30` | Tailwind arbitrary values (no new token) |
| Answer option: incorrect (post-submit) | Destructive color — `text-destructive border-destructive/50 bg-destructive/10` | Destructive token utilities |
| Correct answer revealed (when user answered wrong) | Green label below incorrect option | `text-green-400 text-xs` |
| Score banner: pass (≥ 70%) | Primary accent on score number | `text-primary font-semibold` |
| Score banner: fail (< 70%) | Muted foreground on score number | `text-muted-foreground font-semibold` |
| Locked quiz section | Muted background with opacity | `opacity-50 pointer-events-none` on quiz body |

> **Green color note:** The design system uses OKLCH neutral tokens only. For the correct-answer semantic green, use Tailwind's built-in `green-400` / `green-500` / `green-950` palette utilities — these are the minimum necessary deviation from neutral to convey quiz correctness. Do not introduce a CSS variable.

**Accent reserved for:** "Submit Quiz" primary CTA button, selected answer option ring, "Retake Quiz" secondary CTA. All other interactive elements use `ghost`, `outline`, or `link` variants.

**Source:** `app/globals.css` dark tokens + Phase 3 color contract + Phase 5 quiz semantic requirements.

### New (install required)

| Component | Usage | shadcn Add Command |
|-----------|-------|-------------------|
| `RadioGroup`, `RadioGroupItem` | Answer option single-select (accessible, keyboard-navigable) | `npx shadcn add radio-group` |
| `Progress` | Score percentage bar in results banner | `npx shadcn add progress` |

> **RadioGroup rationale:** Radix `RadioGroup` provides built-in keyboard navigation (arrow keys cycle options), ARIA `role="radiogroup"` + `role="radio"` semantics, and focus management — required for accessible quiz answer selection. Do not implement with raw `<input type="radio">` or custom click handlers.

> **Progress rationale:** The score results banner shows "4 / 5 — 80%" with a visual progress bar. The shadcn `Progress` component maps directly to Radix `@radix-ui/react-progress` and renders the correct fill animation from 0→score on mount.

**Source:** Components dir scan + QUIZ-03 requirement for per-question review with color highlighting + accessibility requirements.

## Interaction Patterns

### Quiz State Machine

The quiz UI has four discrete states. Transitions are one-directional except retake.

```
LOCKED → ACTIVE → SUBMITTED → RESULTS
                                  ↓
                              (Retake) → ACTIVE
```

| State | Trigger | UI Behavior |
|-------|---------|-------------|
| LOCKED | `lesson_progress.completed = false` (or no row) | Quiz section rendered with locked UI: "Take Quiz" button disabled, locked label visible, question list not rendered |
| ACTIVE | User clicks "Take Quiz" (lesson complete) | Questions render, RadioGroup enabled, "Submit Quiz" button visible at bottom |
| SUBMITTED | User clicks "Submit Quiz" with all questions answered | POST to `/api/quiz/submit`, optimistic loading state on button (`disabled + "Submitting..."`) |
| RESULTS | Server returns score + per-question breakdown | Results card replaces question form; score banner, per-question review, "Retake Quiz" button visible |

### Answer Selection

- RadioGroup: clicking anywhere on the answer option row selects it (not just the radio indicator).
- Full-width clickable rows with `cursor-pointer`.
- Selected state: `border-primary ring-1 ring-primary/30` replaces `border-border`.
- Only one option selectable per question (RadioGroup single-select behavior).
- No confirmation needed before changing selection.

### Submit Behavior

- "Submit Quiz" button is `disabled` until all questions have a selected answer.
- When all questions answered: button becomes active (default variant, primary styling).
- On click: button enters loading state — label changes to "Submitting...", `disabled` prop added, no spinner needed.
- Single POST to `/api/quiz/submit` — server scores, returns `{ score, total, pct, breakdown: [{ questionId, correct, selectedAnswer, correctAnswer }] }`.
- On success: transition to RESULTS state, scroll to score banner.
- On error: button returns to active state, inline error copy appears below button.

### Results Display

- Score banner card appears above the question review list.
- Per-question review renders all questions in the same order as ACTIVE state.
- Each option row shows its post-submit state (correct/incorrect/neutral-unselected).
- The user's selected option is highlighted (green if correct, destructive red if incorrect).
- When the user selected the wrong option, the correct option gets the green label "Correct answer: {text}" even though it was not selected.
- The RadioGroup is `disabled` in RESULTS state — no re-selection.

### Retake Behavior

- "Retake Quiz" button resets to ACTIVE state.
- All RadioGroup selections cleared.
- A new `quiz_attempts` row will be written on the next submission (multiple attempts allowed).
- The score shown in RESULTS always reflects the most recent submission.

### Locked State

- The quiz section renders as a card with a lock icon (`Lock` from lucide-react, 16px, `text-muted-foreground`).
- Lock icon + locked label are inline, centered within the card body.
- "Take Quiz" button is rendered with `disabled` prop (not hidden) so the affordance is visible.
- No tooltip needed — the locked label text explains the condition.

**Source:** QUIZ-01 (completion gate), QUIZ-02 (server-side scoring), QUIZ-03 (results review) + Phase 3 interaction patterns (no optimistic UI, inline error states).

## Layout Contract

### Quiz Section on Lesson Page

The quiz section is appended below the transcript section, separated by a `<Separator>`. It uses the same `max-w-[896px] px-8` constraint as the existing lesson page layout.

| Area | Specification |
|------|---------------|
| Lesson page container | Existing: `mx-auto w-full max-w-[896px] px-8 pt-8 pb-16 space-y-6` — no change |
| Quiz section position | Below transcript, above page bottom padding |
| Quiz section separator | `<Separator>` between transcript and quiz section header |
| Quiz section spacing | `space-y-6` consistent with lesson page rhythm |
| Quiz card | Full width of container (`w-full`), no fixed height |

### Active Quiz Layout

| Area | Specification |
|------|---------------|
| Quiz card container | `<Card>` full width, `<CardHeader>` + `<CardContent>` |
| Card header | "Post-Lesson Quiz" (Heading 18px semibold) + question counter (Label 12px muted) — `flex items-center justify-between` |
| Question block | `space-y-3` between question text and answer options |
| Question text | 18px semibold (`text-lg font-semibold`), full width |
| Answer options container | `<RadioGroup>` — `flex flex-col gap-2` (8px between options) |
| Answer option row | Full width, `flex items-center gap-3 p-3 rounded-md border cursor-pointer` |
| Radio indicator | `<RadioGroupItem>` left-aligned, 16px |
| Option label | 14px normal (`text-sm`), flex-1 |
| Gap between question blocks | `lg` (24px) — `space-y-6` on question list container |
| Submit button position | Below last question, right-aligned or full-width (full-width preferred for mobile) |
| Submit button variant | `default` (primary) when active, `disabled` when not all answered |

### Results Layout

| Area | Specification |
|------|---------------|
| Score banner card | Full width, `<Card>` with `CardHeader` + `CardContent` |
| Score banner header | "Quiz Results" (Display 24px semibold) + Pass/Fail badge — `flex items-center justify-between` |
| Score number | `text-3xl font-semibold` — "{N} / {total}" large, pct% small beside it |
| Progress bar | `<Progress value={pct} className="h-2 mt-2">` below score number |
| Per-question review section | Same question list, rendered below score banner, `space-y-4` |
| Per-question answer options | Same layout as ACTIVE but `disabled` RadioGroup, with color overlays |
| Correct/Incorrect label | Inline to the right of the option row, `text-xs` |
| Correct answer reveal | Below the user's incorrect selection: `"Correct answer: {text}"` in `text-green-400 text-xs mt-1 ml-9` (indented past radio indicator) |
| "Retake Quiz" button | Below last question review, right-aligned, `outline` variant |

**Source:** QUIZ-03 success criteria layout description + lesson page layout from `app/dashboard/lesson/[lessonId]/page.tsx` + Phase 2 max-width 896px reading layout pattern.
